# cag-kag-bench

[![CI](https://github.com/mpuodziukas-labs/cag-kag-bench/actions/workflows/ci.yml/badge.svg)](https://github.com/mpuodziukas-labs/cag-kag-bench/actions/workflows/ci.yml)

Cache-augmented generation (CAG) and knowledge-graph-augmented generation (KAG), measured against plain retrieval (RAG) on one synthetic corpus, deterministically, with no network and no model calls.

## What it proves

| Skill | Where it shows |
|---|---|
| RAG | `rag/`: a stdlib BM25 retriever, top-k, an answerer that reads only the retrieved text |
| CAG | `cag/`: the whole corpus packed once under a token budget, an exact-match answer cache, invalidation on any doc edit |
| KAG | `kag/`: a rule-based triple extractor, a multi-hop planner, a provenance path on every answer, refusal on an unsupported edge |
| Context engineering | the same questions answered from a few cited edges, a top-k of retrieved docs, or the full packed corpus; context tokens are reported per method |
| Caching and latency | hit rate and per-query wall time, with a test that a stale entry is never served |
| Evaluation hygiene | seeded dev/test split, tuning on dev only, Wilson 95% intervals, mutation-proven checks |

## 60-second run

```
python3 -m pip install pytest pyyaml
bash scripts/verify.sh              # tests, bench, byte-identical rebuilds, lint, prints GREEN
bash scripts/verify.sh --selftest   # 4 planted defects plus 1 control, prints 5/5
python3 bench.py run                # the table below, plus per-query wall time
```

## Honesty Statement

- The corpus is synthetic: 60 short documents about a fictional company, generated by a seeded script.
- The answerer is a deterministic extractive stub behind an interface. No language model is called.
- The stub, the KAG extractor and the question parser share one sentence grammar. That is why CAG and KAG reach full marks on answerable questions: the numbers measure retrieval coverage and grounding (did the right evidence reach the reader, and can each claim be traced to a document), not model quality and not real-world accuracy.
- Gold answers come from dict lookups on the generator's world model, not from the code under test.
- Questions are split 50/50 with a seed. RAG parameters are tuned on the dev half only; only the test half is reported.

## Limitations

- Template questions over a four-relation grammar; real questions and real documents are messier.
- With 50 test questions the intervals are wide, and the per-hop cells are small (11 and 9 questions for 2 and 3 hops).
- Token counts use a whitespace proxy, not a real tokenizer.
- CAG fits the whole corpus in its budget here; the packer truncates at the first overflow and does not rank.
- Wall times are indicative only and are not stored in any result file.
